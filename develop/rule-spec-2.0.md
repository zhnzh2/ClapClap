## 零、基本参数

| 参数 | 值 | 备注 |
|------|-----|------|
| 最少人数 | **2 人** | 2.0 规则包含双人情况 |
| 最多人数 | **6 人** | 暂定，保留扩展 |
| 人数模式 | 只设上限，不固定 | 2~6 范围内均可开始 |
| 房主提前开始 | 允许，≥2 人即可 | 房主手动点击开始 |
| 中途加入参战 | **不允许** | 对局开始后锁定 |
| 中途观战 | **允许** | 不影响对局状态 |
| 死亡后 | **自动转为观战者** | 可看后续回合和聊天 |
| 座位顺序 | 按加入顺序固定 | 不影响攻击范围 |
| 攻击范围 | **任意存活玩家** | 围成一圈只是现实动作设定 |

## 一、回合流程总览

每个回合分为三个阶段：

### 1.0 击掌阶段
所有玩家同时与左右两侧击掌，形成节奏。不消耗资源，不造成伤害。

### 1.1 出手阶段
所有存活玩家同时做出一个手势。阶段结束时动作冻结。
- 蛤蟆（慢出手）→ 立即死亡，从本回合移除
- 蟆蛤（不合规手势）→ 立即死亡，从本回合移除

### 1.2 结算阶段（A~H 子阶段）

```
A. 资源合法性检查
B. 统一亮招
C. 闪结算（速度层 1）
D. 三连检测与结算（速度层 2）
E. 速度层循环（层 3~12）
F. 死亡与胜负判定
```

## 二、玩家状态模型

### 状态标记

| 状态 | 含义 |
|------|------|
| **存活**（alive） | 生命值 > 0，未因处罚死亡 |
| **死亡**（dead） | 已淘汰，原因记录在案 |
| **观战**（spectating） | 死亡后自动转入，或主动加入 |
| **未操作**（unresolved） | 本回合尚未成为已操作对象 |
| **已操作**（resolved） | 已发生有效交互，不再参与后续结算 |

### 已操作对象的规则

- **不能**：主动攻击别人、被选为目标、被锦囊作用、参与后续速度层的任何操作
- **仍能**：获得被动资源（气、盾、火种、电池、加镐）
- **例外**：被吃掉的闪电不获得电池、被抢镐不获得镐

### 变为已操作对象的事件

1. 使用闪
2. 成功攻击别人
3. 被别人攻击（无论是否造成伤害，包括攻击防御手势未打穿）
4. 使用锦囊成功作用别人
5. 被锦囊成功作用
6. 使用作用于自身的锦囊（加镐）
7. 参与三连

### 不变成已操作对象的事件

1. 你吃/双吃未命中目标
2. 攻击选择放空
3. gi 无任何合法目标（失效）
4. 出资源手势（气/盾）且未被攻击、未被锦囊作用

## 三、资源系统

### 六种资源

| 资源 | 初始值 | 上限 | 获取方式 |
|------|--------|------|----------|
| 生命值 | 1 | 无 | 镐复活恢复 |
| 气 | 0 | 无 | 出"气"手势获得 1 |
| 盾 | 0 | 无 | 出"盾"手势获得 1 |
| 火种 | 0 | 无 | 出 Fire 获得 1 |
| 电池 | 0 | 无 | 出闪电获得 1（被吃/三连中出现吃时不获得） |
| 镐 | 0 | **1** | 出加镐获得 1 / gi 抢镐获得 |

### 死亡类型与时机

| 类型 | 触发 | 移除时机 |
|------|------|----------|
| 蛤蟆 | 出手阶段慢出手 | 出手阶段立即，本回合不在场上 |
| 蟆蛤 | 出手阶段不合规手势 | 出手阶段立即，本回合不在场上 |
| 蚂蚁（爆气/爆盾） | 结算阶段 A，资源不足 | 结算 A 立即，本回合不在场上 |
| 爆镐 | 获得第 2 个镐的瞬间 | 该速度层立即，不参与后续层 |
| 生命值 ≤ 0 | 速度层中承受伤害 | **回合末统一判定**，下回合移出 |

> 处罚死亡（蛤蟆/蟆蛤/蚂蚁）在阶段 A 前即被移出，不参与任何结算。

## 四、速度层定义

### 完整 12 层

| 层 | 名称 | 行为 |
|----|------|------|
| **1** | 闪 | 立即已操作。本回合不能被攻击/锦囊目标，不参与任何后续结算 |
| **2** | 三连 | 检测对象：存活 + 未操作 + 非闪玩家。只看手势类型和克制链 |
| **3** | 你吃 / 双吃 | 含双吃拆分的两个你吃。目标：出破或闪电的未操作玩家 |
| **4** | gi 攻击黑洞 | gi 选择黑洞作为目标。成功后黑洞使用者受 3 点反噬 |
| **5** | 黑洞 | 可拆分 3 段。如在层 4 被 gi 攻击，已操作，拆分作废 |
| **6** | 如来 / Shining | Shining 在此层声明拆分（拆为 2 个闪电，在层 9 结算） |
| **7** | 冷锋 / 烈焰 | 各自攻击或放空 |
| **8** | gi 造成伤害 / gi 抢镐 | 同一 gi 二选一：攻击造成伤害 或 抢镐。必须选目标 |
| **9** | 破 / 闪电 | 含 Shining 拆分的闪电。闪电被吃时不获得电池 |
| **10** | Fire | 攻击或放空。无论已操作与否，仍获得火种 |
| **11** | 无合法目标的 gi | 保持未操作，gi 失效 |
| **12** | 气 / 盾 / 加镐 | 无论已操作与否，仍获得对应资源（被抢镐除外） |

### 层内结算顺序

同一速度层内，按以下步骤执行：

```
1. 后端下发合法目标列表
2. 相关玩家秘密提交目标意向
3. 全部提交后统一公开意向
4. 后端检测冲突
   ├── 无冲突 → 同时结算 → 进入下一层
   └── 有冲突 → 进入协商
5. 协商（最多 3 轮）
   ├── 需玩家明确点击"同意当前方案"或"我要放空"
   ├── 同意的按方案执行
   └── 协商失败 → 未谈拢的放空，谈拢的按约定执行
6. 执行最终方案 → 进入下一层
```

> 当前阶段默认玩家不超时（超时机制延后实现）。

## 五、三连

### 检测条件

三连在层 2 单独检测，**优先于所有后续速度层**。

检测范围：
- 只看**手势类型和克制链**
- **忽略**：gi 互斥规则、玩家已操作状态、防御力、实际能否造成伤害
- 已使用闪的玩家**不参与**三连检测

### 两种三连类型

| 类型 | 手势组合 |
|------|----------|
| 类型一 | gi — 你吃/双吃 — 破 |
| 类型二 | gi — 黑洞 — 其它攻击（非 gi 非黑洞的攻击手势） |

### 三连结果

- 三人之间的攻击全部无效
- 三人立即变为**已操作对象**
- 三连中出闪电且被"吃" → 不获得电池
- 三连中出 Fire → 仍获得火种
- 三连中 gi-黑洞-闪电（无"吃"）→ 闪电仍获得电池

### 人数结构处理

| 结构 | 处理方式 |
|------|----------|
| (1, 1, 1) | 三人直接组成三连 |
| (1, 1, 多) | 由克制多人方的那一方从多人方中选择一人 |
| (1, 多, 多) | 单人方先选 → 被选中者再从自己克制的多人方中选一人 |

### 重叠三连

若存在多组可能的（1,1,多）或（1,多,多）结构，按规则书机制逐个处理：
- 先处理 (1,1,多)，由克制方选择 → 三人已操作
- 再检查剩余未操作玩家是否还能形成三连

### 两组独立三连（6 人）

若场上可独立组成两组三连（共 6 名玩家），**本回合直接结束**：
- 两组三连的 6 人全部变为已操作
- 除资源手势和加镐仍正常结算外，其余攻击和锦囊均无效

## 六、特殊规则

### gi 特殊规则

| 规则 | 说明 |
|------|------|
| gi 不能攻击 gi | 两个出 gi 的玩家不能互指 |
| gi 强制攻击 | 存在合法目标则必须选，不能放空 |
| gi 无合法目标 | 失效，保持未操作 |
| gi 攻击黑洞 | 层 4，成功则黑洞受 3 点反噬 |
| gi 抢镐 | 层 8，选择出加镐的玩家，抢走镐，出镐者无法获得 |
| gi 二选一 | 同一 gi 只能选一个目标：造成伤害 或 抢镐 |

### 2 人局中双方都出 gi

gi 不能互攻，都没有合法目标。两个 gi 都失效，保持未操作。回合只有资源手势结算。

### 黑洞拆分

- 在层 5 声明拆分，拆为 3 个小黑洞
- 每个小黑洞攻击力仍为 5，各造成 1 点伤害
- 三个目标**同时提交**
- 允许两段或三段打同一目标
- 每段**独立检查合法性**：目标必须是未操作对象 + 满足攻击条件
- 某段无合法目标 → 该段放空，其余段正常结算
- 若黑洞使用者在层 4 被 gi 攻击 → 已操作 → 拆分作废

### Shining 拆分

- 在层 6 声明拆分，拆为 2 个闪电
- 拆分出的闪电在**层 9**（破/闪电层）结算，按闪电的完整规则处理
- 每段独立检查合法性
- 某段无合法目标 → 该段放空

### 双吃拆分

- 拆为 2 个你吃
- 均在层 3 结算
- 每段独立选择目标，独立检查合法性

## 七、镐的完整规则

### 获得镐的方式

| 方式 | 速度层 | 条件 |
|------|--------|------|
| 加镐 | 层 12 | 出加镐手势且未被 gi 抢镐 |
| gi 抢镐 | 层 8 | gi 选择出加镐玩家为目标，抢镐成功 |

### 镐的效果

| 效果 | 说明 |
|------|------|
| 抵挡伤害 | 每 1 点伤害消耗 1 个镐，按每段处理 |
| 复活 | 获得镐时 HP ≤ 0 → 恢复 1 点生命值，不获得镐实体 |
| 多段伤害 | 黑洞 3 段同时结算，镐依次消耗。1 个镐挡第 1 段，挡不住第 2、3 段 |

### 爆镐

- 持有镐数量 > 1（上限） → 立即爆镐死亡
- **在该速度层内立即移除**，不参与后续速度层
- 常见触发：gi 抢镐（层 8）→ gi 使用者若已有 1 个镐 → 抢到第 2 个 → 立即爆镐

## 八、攻击与伤害

### 基础攻防

| 情况 | 结果 |
|------|------|
| 攻击力 > 目标防御力 | 攻击成立，造成伤害 |
| 攻击力 < 目标防御力 | 无法选择为目标（攻击手势）/ 无法造成伤害（防御手势） |
| 攻击力 == 防御力，互相攻击 | 对掉，双方已操作，无伤害 |
| 同速无冲突 | 同时发出、命中、扣血、死亡 |

### 攻击后防御归零

玩家决定攻击的瞬间，自身防御力变为 0。这在同速层中可能被其他玩家利用（强杀）。

### 强杀示例

层 9，A 和 B 都出破。A 选择攻击 C（低防御），A 防御归零。B 选择攻击 A → 攻击成立 → A 被强杀。

## 九、冲突与协商

### 冲突类型

| 类型 | 处理 |
|------|------|
| **无冲突**（A→C, B→D） | 同时结算 |
| **一般冲突**（A→B 且 B→A） | 协商，谈不拢则都放空或按攻击力低者放空 |
| **多攻击少**（A→C 且 B→C） | **被攻击方 C 选择**由谁来攻击自己 |
| **锦囊多对一**（A 你吃→B, C 你吃→B） | **被作用方 B 选择**接受谁的作用 |

### 协商协议

每个同速层按以下协议执行：

```
阶段 1: 目标意向提交
  - 后端下发合法目标列表 → 相关玩家聊天讨论 → 秘密提交意向
  - 提交后等待全部到位

阶段 2: 统一公开
  - 全部提交后同时公开
  - 后端检测冲突类型

阶段 3: 冲突处理（如需要）
  - 最多 3 轮协商
  - 每轮玩家明确点击"同意当前方案"或"我要放空"
  - 多攻击少：被攻击方从攻击者中选择一人（其余放空）
  - 三连 (1,1,多)：克制多人方的那一方选择
  - 三连 (1,多,多)：单人方先选 → 被选中者再选

阶段 4: 执行
  - 后端执行最终方案
  - 更新已操作状态 → 进入下一个速度层
```

## 十、胜负与名次

### 胜负判定

| 情况 | 结果 |
|------|------|
| 只剩 1 人存活 | 该玩家获胜 |
| 同回合全员死亡 | **平局**，所有参与者并列 |
| 最后两人同时死亡 | **平局** |

### 名次记录

- 记录**完整名次**
- 同回合死亡的玩家**并列同一名次**
- 名次 = 还存活的玩家数 + 1
- 示例：4 人局，第 3 回合 A 和 B 同时死亡 → A、B 并列第 3 名

### 死亡原因记录

```
正常死亡     — 生命值 ≤ 0（回合末）
爆镐死亡     — 镐超上限（立即）
爆气/爆盾    — 资源超支（阶段 A 立即）
蛤蟆         — 慢出手（出手阶段立即）
蟆蛤         — 不合规手势（出手阶段立即）
```

## 十一、数据记录要求

### 对局记录（多人）

每个回合必须保存：
- 所有参与者及其资源快照
- 所有手势
- 资源合法性检查结果
- 三连判定结果（含选择链路和随机种子）
- 每个速度层的：目标意向 → 冲突 → 协商过程 → 最终方案 → 结算事件
- 伤害事件（来源、目标、伤害量、是否抵挡）
- 镐事件（获得、消耗、抢镐、复活、爆镐）
- 死亡事件（玩家、原因、回合、速度层）
- 回合末资源快照
- 名次更新

### 随机裁定

- 使用**确定性伪随机**：种子 = `battle_id + round_number + speed_layer_index + context`
- 种子和结果均写入对局记录
- 回放直接读取结果，不重新随机

## 十二、暂缓事项

以下机制在当前阶段不做，后续阶段再引入：

- 玩家掉线检测与重连
- 出招超时 / 目标选择超时 / 协商超时
- 主动投降
- 房主转移
- 宽限期（只剩一人在线时）
- 重赛投票

当前阶段默认：所有玩家都按时操作，不存在超时情况。

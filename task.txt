一、当前已完成能力概览
================================================================================

1. 1.0 AI 可玩链路已打通
   - /v1/ai 页面可以进行人机对战。
   - /v1/api/ai/* 由后端生成 AI 动作，客户端不能伪造 AI 动作。
   - AI 支持 easy / normal / hard 三个难度入口。
   - 当前 hard 没有真实模型时安全回退到 heuristic hard。

2. 1.0 AI 基础规则和接口已稳定
   - 动作空间来自 app/v1/constants.py 的 Move 枚举。
   - 动作空间大小为 17。
   - app/ai/space.py 提供动作索引、顺序和指纹。
   - app/ai/engine.py 是统一 select_move 入口。
   - AI 合法动作判断来自 GameEngine.can_afford()。
   - AI 不读取真人本回合动作，只基于回合开始状态副本决策。

3. AI 对战状态、记录和统计已接通
   - AI 对战状态已按用户隔离，不再使用单个全局 AI_STATE 串局。
   - AI battle 记录包含 difficulty、policy_type、seat、action_space_fingerprint、observation_version。
   - 每回合记录 human_move、ai_move、human_seat、ai_seat、ai_inference_ms。
   - 用户战绩中 AI 对局已单独统计，不混入正式真人战绩。

4. 自动评估系统已具备第一版生产力
   - scripts/evaluate_ai.py 支持单组评估和默认矩阵评估。
   - 支持 P1/P2 换边统计、胜率、失败率、双败率、截断率、动作频率、资源均值、推理耗时。
   - 支持 JSON 报告、summary 表格和 JSONL 详细对局日志。
   - 已生成基准报告 reports/ai_eval/baseline_20260630.json。
   - 当前基准：normal vs easy 胜率约 95.2%，hard vs easy 约 98.4%，hard vs normal 100%，非法动作 0，截断 0。

5. 训练和推理基础设施已完成骨架
   - app/ai_env.py 已有轻量训练环境。
   - observation_version = clapclap-v1-public-state-v2。
   - reward_config_version = terminal-v1。
   - 训练 observation 包含 metadata、合法动作 mask 和 history window。
   - training/gym_env.py 提供可选 Gymnasium wrapper 和 action_masks()。
   - requirements-train.txt 已把训练依赖与生产依赖分离。
   - training/train_maskable_ppo.py 支持 dry-run 生成模型 manifest。
   - app/ai/model_runtime.py 已有生产 manifest 校验、模型状态和 heuristic fallback 骨架。

6. 当前验证状态
   - 全量测试最近通过：330 passed。
   - Python 编译检查通过。
   - AI 页面 JS 语法检查通过。


二、后续总体目标
================================================================================

下一阶段的目标不是继续完善“启发式 AI 可玩版”，而是进入真正的模型训练、模型评估、
模型上线和长期迭代体系。

最终希望达成：

1. 能在本地或专用训练环境中训练出第一个 1.0 AI 模型。
2. 模型文件带完整 metadata，并严格绑定规则版本、动作空间、观察空间和奖励配置。
3. 模型必须通过自动评估矩阵后才能进入 deployable 集合。
4. 生产环境只加载模型推理，不训练。
5. 模型推理失败、超时、metadata 不匹配时，hard 自动回退 heuristic，玩家无感。
6. 后续能管理历史模型池、自我博弈、模型晋级和真人数据分析。


三、阶段 A：真正实现训练闭环
================================================================================

目标：

把当前 dry-run 训练骨架升级成可以在本地训练出第一版模型文件的流程。
这一阶段仍不接生产页面，只做离线训练和离线评估。

要做的事：

1. 安装训练依赖
   - 使用 requirements-train.txt。
   - 依赖包括 gymnasium、numpy、torch、stable-baselines3、sb3-contrib。
   - 训练依赖不得加入生产 requirements.txt。
   - 生产 Flask app 不允许 import 训练脚本。

2. 完善 training/gym_env.py
   - 确认 observation vector 的字段顺序稳定。
   - 确认 legal_action_mask 与 action_masks() 完全一致。
   - 确认非法动作不会被模型训练过程选中。
   - 增加 reset(options={"randomize_seat": True}) 的稳定测试。
   - 增加多个 env 实例互不污染的测试。

3. 实现 MaskablePPO 训练循环
   - 在 training/train_maskable_ppo.py 中接入 sb3_contrib MaskablePPO。
   - 第一版对手池只使用 random legal-action AI。
   - 每局随机 AI 控制 P1 或 P2。
   - 支持 total_timesteps、seed、max_rounds、history_window、output_dir 参数。
   - 支持训练日志落盘。
   - 支持 checkpoint 保存。

4. 保存模型 artifact
   - 保存模型权重。
   - 保存 manifest.json。
   - manifest 必须包含：
     rule_version
     action_space_size
     action_space_fingerprint
     action_names
     observation_version
     reward_config_version
     history_window
     max_rounds
     model_version
     inference_adapter
     algorithm
     seed
     total_timesteps
     opponent_pool
     seat_randomization
     created_at
     evaluation result placeholder

5. 增加训练 smoke 测试
   - 不要求 CI 跑真实大训练。
   - 可以提供 --smoke-test 或 --total-timesteps 很小的训练入口。
   - 如果训练依赖缺失，测试应跳过或验证友好错误。
   - 不能让没有训练依赖的生产测试失败。

验收标准：

1. 本地安装训练依赖后，可以跑出一个模型权重文件。
2. 模型目录至少包含 weights + manifest.json。
3. manifest 能通过 validate_model_metadata()。
4. 训练脚本不影响现有生产测试。


四、阶段 B：模型评估与晋级机制
================================================================================

目标：

训练出来的模型不能直接上线，必须先通过固定评估矩阵和晋级规则。
这一阶段把“训练 reward”转化为“真实规则胜率”和“可上线质量门槛”。

要做的事：

1. 扩展 scripts/evaluate_ai.py 支持模型策略
   - 当前评估只支持 easy / normal / hard。
   - 新增 --model-dir 参数。
   - 支持 candidate model vs easy。
   - 支持 candidate model vs normal。
   - 支持 candidate model vs hard heuristic fallback。
   - 支持 candidate model vs historical model。

2. 固定第一版晋级门槛
   - illegal_moves 必须为 0。
   - truncated_rate 必须低于阈值。
   - candidate vs easy 胜率不得低于 normal baseline。
   - candidate vs normal 胜率必须达到约定阈值。
   - P1/P2 胜率差不得过大。
   - 动作分布不能极端坍缩。
   - 双败率不能异常升高。

3. 输出评估报告
   - 每个候选模型输出 reports/ai_eval/<model_version>.json。
   - 报告记录模型 metadata。
   - 报告记录每组对战矩阵结果。
   - 报告记录 seed 和评估命令。
   - 支持 JSONL 详细日志用于复现异常。

4. 增加 promote 脚本
   - 新增 training/promote_model.py 或 scripts/promote_ai_model.py。
   - 输入 dev/candidate 模型目录。
   - 检查 manifest 和评估报告。
   - 通过晋级门槛后复制到 models/ai/v1/deploy。
   - 写入 deploy manifest。
   - 不通过则拒绝 promote，并输出原因。

验收标准：

1. 任意候选模型都有可复现评估报告。
2. 不达标模型不能进入 deploy 目录。
3. deploy 目录中的模型一定带完整 manifest 和评估结果。


五、阶段 C：生产推理 adapter
================================================================================

目标：

让 hard 难度在存在合格 deploy 模型时真正调用模型推理；模型不可用时继续安全回退。

要做的事：

1. 实现 sb3_maskable_ppo_v1 adapter
   - 在 app/ai/model_runtime.py 或 app/ai/model_adapters/ 下实现。
   - 生产启动时加载一次模型。
   - 加载前校验 manifest。
   - 校验 rule_version。
   - 校验 action_space_fingerprint。
   - 校验 observation_version。
   - 校验 reward_config_version。
   - 校验 weights_path。

2. 推理输入
   - 从 GameState 编码 observation vector。
   - 生成 legal_action_mask。
   - 模型只接收 observation + mask。
   - 模型不能直接访问真人本回合动作。

3. 推理输出
   - 输出 action_index。
   - action_index 必须映射回 Move。
   - 输出动作必须在 legal_action_mask 内。
   - 若输出非法动作，立即 fallback heuristic，并记录 reason。

4. 超时和异常降级
   - 使用 CLAPCLAP_AI_INFERENCE_TIMEOUT_MS 配置。
   - 推理异常时 fallback heuristic。
   - 推理超时时 fallback heuristic。
   - metadata mismatch 时 fallback heuristic。
   - 权重缺失时 fallback heuristic。

5. 性能监控
   - 已有 ai_inference_ms / api_elapsed_ms 字段。
   - 后续补充 model_load_ms。
   - 补充 model_status API 或在 /api/modes/status 中显示模型状态。
   - 记录 fallback reason。

验收标准：

1. deploy 模型存在且合法时，hard policy_type = model。
2. deploy 模型缺失或异常时，hard policy_type = heuristic_fallback。
3. 模型异常不会导致 /v1/api/ai/step 失败。
4. battle metadata 能区分 model 与 fallback。


六、阶段 D：模型池与自我博弈
================================================================================

目标：

避免模型只会打随机 AI 或只会打当前启发式。建立长期模型池，降低遗忘和循环克制。

要做的事：

1. 建立模型目录规范
   - models/ai/v1/candidates/<model_version>/
   - models/ai/v1/deploy/
   - models/ai/v1/archive/<model_version>/
   - models/ai/v1/pool/<model_version>/

2. 历史模型池
   - 保存多个通过评估的历史模型。
   - 训练时从 random、normal heuristic、hard heuristic、history models 中抽对手。
   - 控制每类对手采样比例。

3. 自我博弈第一版
   - 不直接只打最新模型。
   - 从历史池抽样。
   - 保留旧模型防止遗忘。
   - 定期对模型池跑矩阵评估。

4. 晋级规则增强
   - 对 easy 不退步。
   - 对 normal 提高或保持。
   - 对 hard heuristic 不明显弱。
   - 对历史池总体成绩提高。
   - 动作分布不坍缩。
   - P1/P2 差异可控。

验收标准：

1. 新模型不会只凭训练 reward 覆盖旧模型。
2. 任意 deploy 模型可以追溯训练参数、评估报告和上一版本。
3. 可以回滚到历史模型。


七、阶段 E：AI 产品体验增强
================================================================================

目标：

当前 AI 模式已经可玩。后续要让用户感受到“这是一个产品功能”，而不是开发调试页。

要做的事：

1. /v1/ai 页面增强
   - 展示当前 AI 实际策略：random / heuristic / model / heuristic_fallback。
   - hard fallback 时给开发态提示，但不打扰普通用户。
   - 展示 AI 推理耗时或简化为“AI 思考中”。
   - 页面可选择真人 P1 / P2。
   - 开局后锁定座位和难度。

2. 回放页增强
   - 展示 AI 难度。
   - 展示 AI policy_type。
   - 展示 model_version。
   - 展示 fallback reason。
   - 展示 AI seat。

3. 用户页增强
   - AI 对局单独筛选。
   - 真人对局和 AI 对局明确分区。
   - 展示 AI 胜负统计趋势。

4. 管理/调试入口
   - 增加只读 AI 状态诊断。
   - 显示 deploy model status。
   - 显示 action_space_fingerprint。
   - 显示 observation_version。

验收标准：

1. 普通用户能清楚知道自己在和什么难度 AI 对战。
2. 开发者能快速判断 hard 是否正在使用模型还是 fallback。
3. 回放和用户页能长期支持 AI 版本追踪。


八、阶段 F：真人数据分析与行为模型
================================================================================

目标：

当网站有足够真人对战数据后，用真实玩家行为改进 AI 对手模型和评估集。

要做的事：

1. 数据抽取
   - 从 battle records 提取 1.0 真人对局。
   - 排除 AI 对局。
   - 提取每回合开始状态。
   - 提取玩家合法动作集合。
   - 提取玩家实际动作。
   - 提取胜负结果。

2. 行为统计
   - 不同资源状态下玩家动作频率。
   - 面对攻击威胁时玩家选择。
   - 闪的使用时机。
   - 镐的使用习惯。
   - 你吃 / 双吃的使用频率。
   - 不同水平玩家策略差异。

3. 行为模型
   - 第一版只做统计对手模型。
   - 后续可做行为克隆。
   - 行为模型可作为评估对手或训练对手。

验收标准：

1. 能生成真人动作频率报告。
2. 能从真人数据构建一个非随机对手策略。
3. 真人数据不会直接污染生产模型，必须经过评估。


九、阶段 G：工程化与部署
================================================================================

目标：

让 AI 模型上线、回滚、验证、排错都可控。

要做的事：

1. 文档
   - docs/ai_1_0_training.md。
   - docs/ai_1_0_deployment.md。
   - docs/ai_1_0_evaluation.md。
   - docs/ai_1_0_metadata.md。

2. CI / 本地检查
   - 单元测试。
   - evaluate smoke。
   - manifest 校验。
   - deploy model 校验。

3. 部署约定
   - CLAPCLAP_AI_MODEL_DIR。
   - CLAPCLAP_AI_INFERENCE_TIMEOUT_MS。
   - 模型文件不进入生产依赖安装流程。
   - Railway 或生产环境只读模型，不训练模型。

4. 回滚机制
   - deploy 目录保留当前模型。
   - archive 保留历史模型。
   - promote 脚本可回滚到指定版本。

验收标准：

1. 新机器可以按文档完成训练、评估、promote 和生产加载。
2. 模型上线失败时可以快速回退。
3. 生产环境不会因为训练依赖缺失而失败。


十、推荐执行顺序
================================================================================

第一批：真实训练最小闭环

1. 安装 requirements-train.txt。

1. 实现 sb3_maskable_ppo_v1 加载。

1. hard 可以真正使用 deploy 模型。

第四批：长期增强

2. 自我博弈。
3. 真人数据分析。

1. 模型可长期迭代。
